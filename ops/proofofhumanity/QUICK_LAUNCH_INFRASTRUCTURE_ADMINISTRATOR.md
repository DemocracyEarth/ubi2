# Quick Launch infrastructure administrator package

This runbook prepares, but does not apply, a one-hour IAM Identity Center permission set named
`PoHQuickLaunchInfrastructureAdministrator`. Its only purpose is to fill the missing, transaction-free
Base Sepolia API-origin prerequisites in AWS account `368426158592`, `us-east-1`. It cannot create an
application stack, create or execute a CloudFormation change set, run an ECS service, retrieve a secret
value, publish an image, fund an account, submit a blockchain transaction or touch mainnet.

The checked-in renderer invokes no AWS API. **Stop before `CreatePermissionSet`.** An existing authorized
non-root administrator—or separately and explicitly authorized break-glass root only when none
exists—must reverify the protected inputs and receive action-time confirmation before applying anything.

## Exact administrator permissions

The inline policy is generated by
[`quick-launch-infrastructure-administrator.ts`](../../apps/proofofhumanity/app/quick-launch-infrastructure-administrator.ts).
It grants only:

| Purpose | Actions | Scope and conditions |
|---|---|---|
| Discover signer metadata | `secretsmanager:ListSecrets` | metadata-only wildcard required by AWS; `us-east-1` only |
| Inspect signer metadata | `DescribeSecret`, `ListSecretVersionIds` | exact protected issuer and sponsor ARNs only |
| Apply release tags | `TagResource` | each exact secret separately; issuer/sponsor purpose plus release tag must be complete and exact |
| Discover topology | five EC2 `Describe*` actions | metadata-only wildcard; `us-east-1` only |
| Tag approved subnets | `ec2:CreateTags` | exactly two pre-approved subnet ARNs; exact Base Sepolia/API-origin/release tags |
| Inspect signer KMS metadata | `kms:DescribeKey` | only supplied customer-managed key ARNs; omitted when AWS-managed keys are used |
| Request TLS | `acm:RequestCertificate` | exactly the Quick Launch hostname, DNS validation, RSA-2048 and three exact release tags |
| Inspect TLS | `ListCertificates`, `DescribeCertificate`, `ListTagsForCertificate` | list is region-bound; inspection requires all three fixed certificate tags |
| Publish ACM validation | Route 53 hosted-zone reads plus `ChangeResourceRecordSets` | exact hosted zone; only `UPSERT` of `CNAME` names matching `_*.quick-launch-api.proofofhumanity.org` |
| Create task execution role | `iam:CreateRole`, `iam:TagRole` | exact role ARN; exact task-execution tags; no permissions boundary in the request |
| Inspect infrastructure roles | five IAM read actions | only the task execution role and exact scoped CloudFormation deployment role |
| Install task policy | `iam:PutRolePolicy` | exact tagged task execution role only |

There is no `GetSecretValue` in the administrator policy. There is also no `PassRole`, secret mutation,
tag removal, network creation/deletion, certificate deletion/export, hosted-zone creation/deletion,
managed-policy attachment, trust update, role deletion, CloudFormation API, ECS API, any ECR API,
SSM, access-key, billing, cryptocurrency, mainnet or Fobal authority.

The wildcard resources are limited to four AWS API shapes that cannot be resource-scoped: secret
metadata listing, EC2 metadata discovery, certificate listing, and certificate request before ACM has
created an ARN. Every one is region-bound; certificate creation is also domain-, method-, algorithm-
and tag-bound. All opaque VPC, subnet, hosted-zone, secret and KMS identifiers must be independently
approved as Quick Launch resources before rendering. Named secret inputs containing `fobal` are rejected.

## Exact task execution role contract

The package renders the trust and inline policy already frozen in
[`QUICK_LAUNCH_TASK_EXECUTION_ROLE.md`](QUICK_LAUNCH_TASK_EXECUTION_ROLE.md). The trust has one
`ecs-tasks.amazonaws.com` principal, fixed source account and a `us-east-1` ECS source ARN. The inline
policy grants only:

- ECR token retrieval plus pull from the one `proof-of-humanity` repository;
- log-stream creation/writes under `/ubi2/poh-quick-launch-api` (not log-group creation);
- `GetSecretValue` on exactly the two approved signer secrets for runtime injection; and
- optional `kms:Decrypt` on exactly their customer-managed keys, only via Secrets Manager in
  `us-east-1`.

The human administrator never receives the task role's runtime secret-read authority. The application
has no task role, and the task execution role has no IAM, CloudFormation, ECS, SSM or secret-write
permission.

## Administrator handoff — pause before apply

An existing administrator must perform read-only discovery and verify:

1. sanitized STS identity is an approved non-root administrator in account `368426158592` (or root has
   been explicitly authorized for this one bootstrap only);
2. the Identity Center instance, workforce USER and account assignment are exact;
3. the two supplied secrets are the unique metadata matches for `release=poh-quick-launch-v1` and
   `purpose=issuer|sponsor`, without calling `GetSecretValue`;
4. any supplied KMS keys are the keys named by secret metadata, without decrypting anything;
5. both subnets belong to the approved VPC, are public, occupy the supplied distinct AZs and are not
   shared with or tagged for Fobal;
6. the hosted zone is public `proofofhumanity.org`, and the deployment role has the fixed name and a
   separately reviewed Quick Launch-only policy;
7. the already published ECR digest and terminal zero-Critical/High scan were independently verified by
   the existing scoped deployment lane; this permission set has no ECR API;
8. the live renderer output matches every independently reviewed canonical hash and still states
   `transactionFree=true`, `mutatesAws=false`, `applyAuthorized=false`, and `pauseBeforeApply=true`.

Then stop immediately before `sso-admin:CreatePermissionSet`. Creating the permission set, installing
its policy, assigning it, provisioning it, and logging into it each require the documented action-time
sequence and separate confirmation. Do not combine that bootstrap with certificate, tag or IAM-role
writes.

After a freshly provisioned one-hour session is separately authorized, execute only the dependency-
ordered `afterFreshAdministratorLogin` request plan, pausing before each mutating step. Hash and read
back every document. Remove the temporary assignment after the prerequisites are independently verified.
The package deliberately stops before any CloudFormation stack/change-set call.

## Residual authorization limits

AWS IAM has no condition key for the trust-policy bytes supplied to `CreateRole` or the policy name and
document bytes supplied to `PutRolePolicy`. Route 53 can constrain record name, type and action, but not
the record value. Therefore the one-hour principal has payload discretion on the exact task role and
DNS validation CNAME only.

Compensating controls are mandatory: independently approved canonical hashes, action-time request
comparison, one call only, CloudTrail evidence, immediate canonical read-back, ACM-returned CNAME value
comparison, zero managed policies, and removal of the temporary assignment. Any mismatch or unavailable
read-back blocks progress; never broaden the policy to bypass it.

Run the failure-path test:

```sh
pnpm --filter @ubi2/proofofhumanity \
  test:quick-launch-infrastructure-administrator
```

It pins the complete action allowlist and fixture hashes; proves missing, altered or extra tags fail;
rejects wrong accounts/regions/resources, same-AZ or duplicate subnets and Fobal-named secrets; and proves
secret-value access, unrelated IAM, CloudFormation, ECS, application deployment and destructive actions
remain absent. A passing local test is not evidence that any AWS prerequisite exists or is ready.
